# CONVERGE Offline Prompt Generator and Validator

CONVERGE Offline is a Scala 3 application that computes and empirically validates a precise prompt for a specialized LLM agent from a rich EngineerIntent. It uses local models served by Ollama, keeps the engineer's task specification separate from model proposals, measures routing behavior against a real agent catalog, can repair ambiguous catalog boundaries, can measure candidate anchor phrases in an embedding space, and writes the resulting prompt together with reproducible evidence.

The repository contains the CONVERGE prompt-generation application itself. It is not a template for the target application that an LLM later generates or modifies. The target application is a separate repository and may have any directory structure.

## What each source file does

| File | Responsibility |
| --- | --- |
| `Domain.scala` | Defines runtime configuration, EngineerIntent, TaskIR, agent, routing, anchor, plan, catalog-repair, and report data types. It also loads and validates every JSON input before Ollama is contacted. |
| `OllamaClient.scala` | Implements HTTP calls to the local Ollama `/api/version`, `/api/tags`, `/api/generate`, and `/api/embed` endpoints and records model usage metadata. |
| `Geometry.scala` | Implements dot products, vector normalization, centroids, cosine similarity, and Wilson confidence intervals. |
| `CandidatePhraseCollector.scala` | Collects candidate phrases from EngineerIntent and agent metadata and can ask the local generative model for bounded additional phrase hypotheses. It also builds the frozen reference-text set for each agent from the catalog and labeled development requests. |
| `AnchorDiscovery.scala` | Embeds candidate and reference texts, computes target-versus-rival geometric margins, measures actual routing pull and spill with the routing model, removes redundant candidates, and selects positive anchors that pass the configured thresholds. |
| `Router.scala` | Performs repeated routing trials, catalog-order perturbations, pairwise catalog repair, simulated action-plan probing, and the 2 by 2 query-expansion versus catalog-repair study. |
| `PromptRenderer.scala` | Defines JSON schemas, externally ratifies LLM-proposed TaskIR and action plans, deterministically renders the routing request and specialist prompt, and implements the generic-LLM prompt baseline. |
| `Main.scala` | Provides the command-line entry point, orchestrates the complete experiment, optionally checks a separate target repository, and writes all output artifacts. |

## Runtime input provenance

`config/engineer-intent.json` is supplied by the engineer or by an upstream engineering interface whose result the engineer has already approved. It is the authoritative task specification. Ollama is not allowed to broaden it.

`config/agents.json` is the normalized current agent catalog for the multi-agent system being optimized. The original catalog may have been written by a human architect or generated by an earlier agent-generation process. For one CONVERGE run it is treated as the baseline routing configuration.

`config/authority.json` is supplied by the system architect. It independently states which agent owns each artifact-class and operation pair. The router is tested against this authority rather than being allowed to define its own ground truth.

`config/constitution.json` is supplied by the system or security architect. It contains global restrictions that a model proposal cannot weaken.

`tests/routing-development.json` contains labeled cases that may be used during catalog repair and agent-reference construction.

`tests/routing-confirmation.json` contains held-out cases. The application loads them at startup so that their hash is frozen, but does not use them for catalog repair or anchor reference construction. They are evaluated only after optimization.

## Validate the JSON configuration without Ollama

Before spending time on model calls, validate the input files and authority relationships.

```bash
sbt "run --validate-only"
```

This mode performs the following checks without contacting Ollama.

1. All six required JSON files exist and parse.
2. Agent IDs are unique.
3. EngineerIntent names existing expected and handoff owners.
4. `authority.json` assigns the EngineerIntent artifact and operation to the same expected owner.
5. Every owner named by authority.json exists in agents.json.
6. Every agent has a nonempty router description, owned-artifact set, and writable-path set.
7. The expected owner declares the EngineerIntent artifact class.
8. Every allowed write is covered by that owner's writable paths.
9. EngineerIntent includes every effect that the expected owner's catalog profile forbids.
10. Allowed and forbidden writes do not overlap.
11. The constitutionally required forbidden effects are present.
12. Allowed and forbidden effects do not directly contradict one another.
13. Required evidence and handoff data are present when the constitution requires them.
14. Routing test IDs are unique and every test refers only to existing agents.

If this command fails, fix the configuration before running the LLM experiment.

## Run the minimal Ollama experiment

The minimal run uses the generative model and keeps embedding-based anchor discovery disabled.

```bash
export OLLAMA_MODEL=qwen3:8b
export CONVERGE_RUN_ANCHORS=false
export CONVERGE_ROUTE_TRIALS=5
export CONVERGE_PLAN_TRIALS=5
export CONVERGE_OUT=out/run-minimal

sbt run
```

When anchor discovery is disabled, the deterministic prompt renderer uses the positive anchor terms already supplied in EngineerIntent. No embedding model is required.

## Run with embedding-based anchor discovery

Enable the full anchor experiment.

```bash
export OLLAMA_MODEL=qwen3:8b
export CONVERGE_EMBEDDING_MODEL=qwen3-embedding
export CONVERGE_RUN_ANCHORS=true
export CONVERGE_GENERATE_CANDIDATES=true
export CONVERGE_ROUTE_TRIALS=20
export CONVERGE_PLAN_TRIALS=20
export CONVERGE_OUT=out/run-anchors

sbt run
```

During this run, the Scala controller performs the following operations.

1. It constructs each agent's frozen reference-text set from the current catalog and labeled development requests.
2. It gathers candidate phrases from EngineerIntent and structured agent metadata.
3. It optionally asks the generative model for bounded additional candidate phrases. These are hypotheses only.
4. It sends all reference and candidate texts to Ollama `/api/embed` using the configured embedding model.
5. It computes a centroid for every agent reference set.
6. It computes the cosine proximity of every candidate phrase to the target centroid and to every rival centroid.
7. It computes the geometric target-versus-strongest-rival margin.
8. It inserts each candidate phrase into controlled routing requests and measures the actual change in target routing mass.
9. It measures spill, meaning the increase in incorrect target routing on non-target development requests.
10. It computes `targetMassGain - gamma * spill`.
11. It removes candidates that are too similar to an already selected phrase.
12. It selects no more than the configured anchor limit.
13. It gives the selected original phrases to the deterministic prompt renderer. No vector is converted back into English.

## Run a stronger empirical study

A more stable experiment uses more repeated trials and tighter acceptance thresholds.

```bash

export CONVERGE_GENERATE_CANDIDATES=true

export CONVERGE_PLAN_TRIALS=50

export CONVERGE_CATALOG_CANDIDATES=4
export CONVERGE_MAX_CATALOG_EDITS=4
export CONVERGE_MIN_EXPECTED_RATE=0.80
export CONVERGE_MIN_MARGIN=0.20
export CONVERGE_MIN_GEOMETRIC_MARGIN=0.05
export CONVERGE_MIN_BEHAVIORAL_SCORE=0.02
```

## Optional concrete target-repository oracle

The target application is external to this repository. It can have any structure.

After a specialist agent has modified a disposable target worktree, point CONVERGE at that repository.

```bash
export CONVERGE_REPO=/absolute/path/to/target-application
export CONVERGE_RUN_ORACLE=true
export CONVERGE_OUT=out/run-with-oracle

sbt run
```

The concrete oracle performs these checks after the normal model experiment.

1. It runs `git diff --name-only` in the target repository.
2. It checks that all changed paths are allowed by EngineerIntent.
3. It checks that every required writable artifact appears in the diff.
4. It opens the first EngineerIntent artifact locator and checks that the requested new version is present and the old version is absent.
5. It executes the first EngineerIntent validation command using the operating-system shell.
6. It records the command exit status and a SHA-256 hash of the command output.

The concrete oracle does not generate the target application and does not assume that the target application uses the CONVERGE repository layout.

## Output files

A completed run writes the following files under `CONVERGE_OUT`.

```text
computed-prompt.txt
computed-routing-request.txt
task-ir.json
final-catalog.json
report.json
summary.csv
anchors.csv
```

`computed-prompt.txt` is the specialist prompt computed by CONVERGE.

`computed-routing-request.txt` is the no-answer-leak request used for the final routing experiment. It describes the artifact, operation, scope, boundaries, validation, and handoff without telling the router which agent is expected to win.

`task-ir.json` is the canonical TaskIR accepted by the external Scala ratifier.

`final-catalog.json` is the catalog after any admitted pairwise routing repairs.

`summary.csv` compares the four prompt conditions: vague seed, manually precise expert prompt, generic LLM rewrite, and full CONVERGE.

`anchors.csv` records candidate provenance, target similarity, strongest rival, rival similarity, geometric margin, target routing gain, spill, behavioral score, and whether the candidate was selected. If anchor discovery is disabled, the file contains only its header because no empirical anchor measurements were performed.

`report.json` is the complete machine-readable experimental record. It contains model digests, input hashes, routing evaluations, catalog-repair history, TaskIR proposal attempts, anchor discovery, prompt-variant evaluations, the 2 by 2 study, held-out confirmation, optional concrete-oracle evidence, and the suite-relative certificate.

If TaskIR compilation is rejected, the application writes `report.json` and `final-catalog.json` and then exits with an error instead of fabricating a prompt.

## How to read the primary routing metrics

For a routing case with N repeated trials, let `expectedRate` be the fraction selecting the authoritative owner and let `strongestRivalRate` be the largest fraction achieved by any other selection.

The reported routing margin is.

```text
margin = expectedRate - strongestRivalRate
```

The case passes only when all of the following are true.

1. The aggregate winner is the expected owner.
2. `expectedRate` is at least `CONVERGE_MIN_EXPECTED_RATE`.
3. `margin` is at least `CONVERGE_MIN_MARGIN`.
4. No trial selects an agent listed in that test's `mustNot` set.

The final condition deliberately makes protected boundaries strict.

## How to read anchor metrics

For each candidate phrase, the embedding model produces a vector. Scala keeps that vector attached to the original phrase. It never decodes vector coordinates into words.

Scala computes.

```text
targetSimilarity = cosine(candidateVector, targetAgentCentroid)

rivalSimilarity = largest cosine(candidateVector, any rival centroid)

geometricMargin = targetSimilarity - rivalSimilarity
```

The actual router experiment then computes.

```text
targetMassGain = target routing mass with candidate - target routing mass without candidate

spill = max(0, incorrect target routing mass on non-target requests with candidate - baseline incorrect target routing mass)

discriminativeScore = targetMassGain - CONVERGE_ANCHOR_GAMMA * spill
```

A phrase is considered for positive selection only if it was marked eligible by its provenance, its geometric margin and behavioral score meet the configured thresholds, and its target mass gain is strictly positive. A later candidate is skipped when it is too similar to an already selected candidate under the redundancy threshold.

## The 2 by 2 study

The program separates the effect of current-query expansion from the effect of persistent catalog repair by evaluating four cells.

```text
q0-c0  raw query, initial catalog
q1-c0  expanded query, initial catalog
q0-c1  raw query, repaired catalog
q1-c1  expanded query, repaired catalog
```

The report records the query effect without catalog repair, query effect with catalog repair, catalog effect without query expansion, catalog effect with query expansion, and the interaction term.

## Important claim boundary

The final certificate is a suite-relative bounded empirical fixpoint. It says that the recorded finite process passed the recorded checks for the recorded model digests, EngineerIntent, agent catalog, authority rules, constitution, routing suites, thresholds, and perturbation schedule.

It does not prove correct behavior for a different model, a future catalog, an arbitrary unseen request, or unrestricted real tool execution. Model, catalog, authority, constitution, or test-suite changes require a new run.

## Troubleshooting

If `sbt clean compile` cannot resolve dependencies, the machine needs network access for the first build or a pre-populated sbt and Coursier cache. After Scala and ujson artifacts are cached, compilation can be performed without downloading them again.

If CONVERGE cannot reach Ollama, verify that `ollama serve` is running and that `OLLAMA_URL` includes `/api`.

If the generative model is reported missing, run.

```bash
ollama pull qwen3:8b
```

If anchor discovery reports the embedding model missing, run.

```bash
ollama pull qwen3-embedding
```

If `--validate-only` reports an authority mismatch, fix `engineer-intent.json` or `authority.json`. Do not repair this by changing the router description because the authority map is the normative source of ownership.

If the concrete oracle reports a write-set failure, inspect `git diff --name-only` in the target repository and compare the paths with `EngineerIntent.allowedWrites`.
